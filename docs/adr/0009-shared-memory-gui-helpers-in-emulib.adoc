# ADR-0009: Shared Memory GUI Helpers Live in emuLib

## Status
Accepted

## Context
The four bundled memory plugins (`byte-mem`, `ram-mem`, `rasp-mem`, `ssem-mem`) each carried a near-identical `EraseMemoryAction` (clear the context, refresh the table model) and repeated the same Swing background scaffolding in their Dump and Load actions: disable the action, run the work in a `SwingWorker`, re-enable in `done()`, and unwrap the cause for an error dialog + log. Bug fixes and behavior changes had to be repeated across eight sites plus four action copies. emuLib already owns reusable UI helpers shared across emuStudio repositories (see ADR-0008), so this shared plugin-facing code belongs there rather than in an emuStudio-internal module.

## Decision
Add two helpers to emuLib package `net.emustudio.emulib.runtime.ui`:

* `EraseMemoryAction(AbstractTableModel, MemoryContext<?>, Icon)` - a reusable action that clears the context and fires a table refresh. The icon is passed in by the caller; the action does not self-resolve it, because `GUI.loadIcon` uses the caller's classloader (`StackWalker`) and a shared class would otherwise miss plugin resources. Each plugin resolves its own icon at the call site and hands the `Icon` in.
* `GUI.runInBackground(Action, Unchecked.RunnableWhichCanThrow, Runnable onSuccess, Consumer<Throwable> onError)` - a static helper wrapping the disable/`SwingWorker`/re-enable/unwrap-cause pattern. The action is re-enabled after the success/error callbacks run, so callers that wait on the action's enabled state observe a completed operation.

Each memory plugin drops its own `EraseMemoryAction` copy and routes Dump/Load through `runInBackground`. Plugin-specific behavior (dump/load bodies, program-location handling, per-plugin error text and log messages) stays in each plugin as lambdas.

## Consequences
One source of truth for the shared memory GUI plumbing; four `EraseMemoryAction` copies and eight hand-rolled `SwingWorker` blocks collapse into single implementations. `ssem-mem`'s Load now performs its memory write on the background thread, matching the other three plugins instead of doing it in `done()`. The bundled memory plugins require emuLib >= 12.1.0. Per-plugin `EraseMemoryAction` tests are removed; coverage moves to a single `EraseMemoryActionTest` in emuLib.
