# ADR-001: Self-contain disassembler bit/format helpers

## Status
Accepted

## Context
emuLib exposed two public helpers that were only meaningful for the disassemblers
generated by edigen:

* `BitOperations` - an ordered pipeline of `Bits` transformations.
* `StringUtils.format(char, Bits)` - rendered a decoded value using a mnemonic
  format character.

`StringUtils` also carried `shorten(...)`, used solely by `ShortenedString`.
None of these were part of the hand-written plugin API; they leaked
edigen's code-generation details into emuLib's public surface.

## Decision
* edigen now generates the bit-operation pipeline and the value-formatting logic
  directly into the `Disassembler` it produces (`Disassembler.edt`). Generated
  code depends only on `Bits`.
* `ShortenedString` absorbs the `shorten` logic as a private method.
* `BitOperations` and `StringUtils` are removed from emuLib's public API.
* `Bits` stays in emuLib: it is part of `DecodedInstruction` and is used directly
  by ssem-cpu.

This breaks the emuLib API (next release is 13.0.0) and requires edigen
(emustudio/edigen#90) and emuLib (emustudio/emuLib#121) to ship together.

## Consequences
* Smaller emuLib public surface; edigen's generation concerns no longer leak into it.
* Generated disassemblers are self-contained apart from `Bits`.
* Plugins must be rebuilt with the matching emuLib and edigen versions.
* Disassembly output is unchanged (verified by the 8080/z80 disassembler tests).
